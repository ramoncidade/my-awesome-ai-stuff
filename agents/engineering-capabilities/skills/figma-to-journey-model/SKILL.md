# Figma to Journey Model

## Procedure
1. Extract available screen, component, variant and token metadata from authorized design evidence.
2. Identify actors, entry points, actions, states, transitions and decision points.
3. Connect journey states to business rules and API interactions when evidence exists.
4. Record missing screens, unclear transitions and assumptions explicitly.
5. Map design elements to documented Design System components.
6. Present the journey model for human validation before implementation planning.
7. Compare implementation against the validated model and record discrepancies.

## Output
Journey model, evidence references, open questions, Design System mapping and validation checklist.

## Safety
Do not invent screens, metadata, rules or API behavior. Respect design access permissions and mark incomplete evidence.
